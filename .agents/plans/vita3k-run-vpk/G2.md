Decision: **Pass.** Recorded 2026-10-02. Gate definition: [04-acceptance-gates.md](04-acceptance-gates.md), section "WP6 — macOS gate G2".

The skill's `doctor` and `run` commands work on macOS with the real Vita3K, from an instance installed by following `references/install.md`. The portable layout isolates the instance, no dialog blocked the boot, and every expected verdict and exit code was observed. The gate needed no script change. One optional change was made afterwards and is described under "Script change". One emulator behavior differs from [G1.md](G1.md): on macOS `SIGTERM` did not stop Vita3K in the install launch either. The script's stop sequence already handles it.

WP5 is still open. This record does not prove anything about Linux.

## Differences from G1 that the documents or the Linux host should know

1. **`SIGTERM` did not stop Vita3K on macOS in any launch.** Observed for 5 s on the scratch copy, with and without an app. In the skill runs both launches end by `SIGKILL` after the 2-second grace period. A run costs about 4 s more than its evidence needs. No script change: the stop function already escalates.
2. **Renderer.** macOS uses Vita3K's default, Vulkan through MoltenVK (`Vulkan device: Apple M4 Max`). The script does not touch `backend-renderer` in `host` mode.
3. **stdout noise.** MoltenVK and Qt print lines that are not log lines (`[mvk-info] …`, a tab-indented extension list, and `qt.…` lines). They count as level `?`. In the first passing run that was 191 of 208 lines in the install launch and 387 of 472 lines in the boot launch. They do not affect expectations.
4. **`xattr`.** A different `xattr` earlier on `PATH` (here a Python shim) rejects `-r`. The reference uses `/usr/bin/xattr`. With no quarantine attribute present the command exits 0. Whether macOS blocks an app that does carry the attribute was not tested.
5. **`config.yml`.** The rewritten file has 181 lines, starts with `---`, ends with the YAML document-end line `...`, and holds an absolute `pref-path`. As on Linux, Vita3K drops `check-for-updates` on rewrite, and the script adds it again. See "Script change" below.
6. **Emulator-owned files.** The boot launch wrote `ux0/user/time.xml` only. `ux0/user/00/user.xml` exists and did not change during a boot launch. The script's two patterns covered everything: `created` and `modified` held only `build.txt`.
7. **`emulator.sha256` on macOS** is the hash of the executable inside the bundle. It cannot be compared with the release digest, which is the hash of the DMG. The reference says so.

## Script change

Not required by the gate. Every step above passed without it.

`upsert_config_text` appended a missing key at the end of `config.yml`. Vita3K ends its rewritten file with the YAML document-end line `...`, so the key landed after that line, in what YAML reads as a second document. Every gate run before the change booted with the key in that place. No copy of such a file was kept, because Vita3K rewrites the file at each start. The only key this affects today is `check-for-updates`, which build 4111 does not know and drops. The function now inserts missing keys before a trailing `...` line. Test: `test_upsert_adds_keys_inside_the_yaml_document` in `tests/test_core.py`.

After the change the pass run was repeated on the real emulator: exit 0, verdict `pass`, `build.txt` under `modified`, no leftover process, personal directory unchanged. `config.yml` kept its 181 lines and its final `...` line. That run shows that Vita3K accepts the file the script now writes. Where the script places the key is shown by the unit test, not by the run.

The Linux gate host has not run this change with the real emulator. WP5 covers it: its first run seeds a full `config.yml`.
