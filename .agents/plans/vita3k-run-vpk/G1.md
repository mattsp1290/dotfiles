# G1 — Headless Linux feasibility gate record

Decision: **Go.** Recorded 2026-10-02. Gate definition: [01-fixture-and-headless-gate.md](01-fixture-and-headless-gate.md).

Vita3K installs and boots the bevypoc fixture on this host under Xvfb with no human interaction. The app writes `ux0:data/bevypoc/build.txt` with the correct source SHA about 2 seconds after launch. The run produced seven deviations from the plan. Five correct a plan finding or assumption. Two are new facts (the glibc requirement and the black Vulkan frame). Each has a working alternative, listed under Deviations. WP3 must implement the recipe in this record, not the original text of [02-runner-script.md](02-runner-script.md) where the two differ. The plan files were updated to match.

## The working recipe

Isolation environment for every invocation:

```text
XDG_CONFIG_HOME=$VITA3K_AGENT_HOME/xdg/config
XDG_CACHE_HOME=$VITA3K_AGENT_HOME/xdg/cache
XDG_DATA_HOME=$VITA3K_AGENT_HOME/xdg/data
```

Renderer profile **P2**:

```text
config.yml:   backend-renderer: OpenGL
environment:  LIBGL_ALWAYS_SOFTWARE=1  __GLX_VENDOR_LIBRARY_NAME=mesa
```

Sequence:

1. Start `Xvfb -displayfd <fd> -screen 0 1280x800x24 -nolisten tcp`. Export `DISPLAY`.
2. Upsert the seed keys in `config.yml`.
3. **Install launch**: `<binary> -- <vpk>`. Wait until `ux0/app/<TITLE_ID>/eboot.bin` exists and stdout contains `installed successfully!` (about 1 second). Send `SIGTERM` to the process group. It exits in about 0.1 seconds, because no app is running.
4. **Boot launch**: `<binary> -r <TITLE_ID>`. The app starts about 1 second after launch.
5. Wait for evidence. Take the screenshot with `xwd -root -silent`.
6. Stop: send `SIGTERM` to the process group, wait 2 seconds, send `SIGKILL` to the process group. Wait until the process group is empty. Then stop Xvfb.

## Deviations from the plan

1. **The current `continuous` build does not start on this host.** Upstream moved its CI to Ubuntu 26.04 on 2026-10-02 (commit `7702ca02`, build 4112). Builds from 4112 on need `GLIBC_2.43`. This host has glibc 2.39. Build **4111** is the newest build that starts here.
2. **Versioned pins exist.** `Vita3K/Vita3K-builds` publishes one release per build number, each with `Vita3K-aarch64.AppImage` and an asset digest. F10 said no pin exists. That was wrong.
3. **No offscreen Qt platform.** The version probe needs Xvfb (check 1).
4. **The VPK path needs a `--` separator.** `<binary> <absolute path>` ignores the path: the argument parser accepts Windows-style options, so a leading `/` is read as an option. `<binary> -- <path>` works.
5. **A positional VPK installs and does not boot.** The log says `Content installed, will auto-boot: BEVYPOC01`, and the app never starts. The app list shows the title, idle, for 180 s. A separate launch with `-r <TITLE_ID>` boots it. F12 and A2 were wrong on this point.
6. **Software Vulkan shows a black game window in the screenshot.** Software OpenGL shows the frame.
7. **`SIGTERM` does not stop a running app.** Use `SIGTERM`, a 2-second wait, then `SIGKILL` (check 9).

## Other observations for WP3 and the references

- Vita3K itself writes `ux0/user/time.xml` and `ux0/user/00/user.xml`. The filesystem diff must not present them as app evidence.
- The installed tree for bevypoc is `ux0/app/BEVYPOC01/eboot.bin` and `ux0/app/BEVYPOC01/sce_sys/param.sfo`.
- Without firmware the log shows `|E|` lines for `os0:kd/bootimage.skprx` and `os0:kd/sysmodule.skprx`, each followed by `Ignoring this error.` bevypoc boots anyway. Error-level lines are normal in a healthy run. This supports D5: log severity must not decide the verdict.
- Every file access is logged. Opens are `|I| [export_sceIoOpen]: Opening file: ux0:/data/bevypoc/build.txt` and `|T| [open_file]: sceIoOpen: Opening file …`. A file that the app probes and does not find is logged at error level: `|E| [stat_file]: Missing file at "<host path>" (target path: ux0:/data/bevypoc/server.txt)`. These lines are useful evidence of what the app tried to read and write. They also mean that an app which probes optional files produces `|E|` lines in a healthy run.
- bevypoc's own failure line with no `server.txt`: `*** TTY: SpacetimeDB unavailable: ` followed by `*** TTY: config: No such file or directory (os error 2)`, repeated every 3 s.
- The emulator fetches a compatibility database from the network at start (`DB is up to date`). It also logs `DB not found at …/app_compat_db.xml` on the first run.
